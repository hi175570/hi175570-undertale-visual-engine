# Hi175570's Undertale Visual Engine

**Hi175570 的 Undertale 图形化战斗引擎**

在画布上拖放弹幕，用 Workspace 积木、节点连接和时间轴编排战斗。编辑器内置在游戏中，编译后的程序也能制作、保存并运行战斗，不要求使用者安装 GameMaker 或为内建功能编写 GML。

作者与维护者：[hi175570](https://github.com/hi175570)。本项目直接基于 [Undertale Engine Ultra](https://github.com/znm2500/Undertale-Engine-Ultra)，后者继承自 TML 的 [UndertaleEngine](https://github.com/TML233/UndertaleEngine)。保留原有游戏运行时，在此基础上扩展图形化编辑器；不是 Undertale 官方工具。来源与许可边界见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

### 主要特色

- 场景拖放、分组控制、旋转与时间轴定格编辑。
- Workspace 积木拖放、拆分拼接、贝塞尔节点连接、等待、循环和公式。
- 骨头、GB、战斗框、平台及其他攻击的可视化创建与控制。
- 敌人部件/动画编辑、音效与音乐选择、灵魂模式和画面特效。
- 独立战斗存档、资源目录与运行时恢复；编辑器和正常开始共用战斗数据。

### 获取与构建

本仓库发布源码，不包含作者的私人战斗存档、编译缓存或 Windows 安装包。用 GameMaker 打开根目录的 `UNDERTALE Engine Ultra.yyp`；工程文件暂保留原名，以免破坏已有构建工具路径。

**首次构建请先阅读 [字体准备说明](docs/FONT_SETUP.md)**：部分本机字体尚未确认再分发许可，因此不随公开源码上传；本机现有文件不会被删除。最近实际使用的构建 Runtime 为 GameMaker Beta `2026.100.0.1090`。

## 1. 项目定位与核心原则

Battle Editor 不是脱离游戏运行时的动画演示器。编辑器保存的是结构化攻击工程，预览和正常游戏都会把这些数据映射到真实的 Battle Core 对象与函数，例如 `Battle_MakeBone`、`Battle_MakeGB`、`Battle_MakeSlash`、`Battle_MakeTrueKnife`、`Battle_MakeBone3D`、`Battle_MakeBone4D`、`Battle_MakePlatform`、Battle Board 与 TextTyper。

核心约束如下：

1. Battle Core 是唯一战斗真相来源。Editor 可以被移除，Battle Core 仍应独立工作；Editor 不维护第二套假骨头、假框、假伤害或假时间系统。
2. 预览和正式怪物回合尽量走相同的生成、控制、伤害、裁剪和生命周期路径。编辑器专用代码只负责编辑状态、冻结、选择、序列化和安全清理。
3. 通用控制按目标“具有什么能力”开放，而不是按对象名字写死白名单。能移动的对象可以移动，能旋转的对象可以旋转，能拉伸或改尺寸的对象才显示相应属性。
4. 系统对象可以成为控制目标，但不能成为阵列函数的复制模板。玩家、灵魂、HUD、按钮和战斗框等系统目标不能被批量克隆。
5. 排列函数是算法，不是 Bone 专属对象类型。椭圆阵、波浪、长廊、物理散射、骨墙等默认生成 Bone；选择一个普通可实例化对象作为模板时，运行时复制它并把副本交给同一排列算法。
6. 编译通过只证明 GML 可以生成目标，不证明按钮、交互、动画、伤害或存档在 Runner 中正确。验证状态必须明确区分“代码存在”“完整编译”“Runner 实测”“用户确认”。

## 2. 工程与运行环境

编辑器的专用界面采用独立透明绘制层，在游戏最终滤镜之后合成：Workspace、菜单、公式说明、时间轴和工具标记不受像素化、反色、波动等游戏效果影响。敌人、弹幕、战斗文本、HUD、战斗框和攻击放置预览仍走原游戏渲染链。界面保留原像素字体与字符回退，仅使用窗口实际分辨率绘制，不修改游戏相机、布局逻辑坐标或输入坐标。界面隐藏时跳过这一层；窗口尺寸未变时复用 surface。分层验证记录见 `docs/EDITOR_COMPOSITE_BATCH.md`。

- GameMaker 工程：`UNDERTALE Engine Ultra.yyp`
- 语言：GameMaker Language（GML）
- 当前战斗编辑器存档格式：`uteu_attack_editor`
- 当前格式版本：`32`
- 存档根目录：运行数据同级的 `save/`；每个命名存档都是一个独立文件夹，不依赖作者电脑的绝对路径。
- 当前已使用的本机完整编译运行时：GameMaker Beta `2026.100.0.1090`
- 逻辑时间基准：`GAME_FPS`，当前时间轴按 60 FPS 语义展示和计算；Runner 的实际刷新率通过 `global.delta_time_factor` 归一化。
- 逻辑画面和 GUI：`640 × 480`。退出编辑器时保持统一输出 Surface；不会通过放大相机去补偿房间尺寸，也不会把后续场景缩小或像素化。

主要目录：

```text

objects/                       游戏对象、战斗对象与编辑器对象
rooms/                         房间与场景
scripts/BattleEditor_Core/     编辑器数据、运行映射、Workspace 与辅助函数
scripts/Battle_Extensions/     Battle Core 扩展、伤害、KR、护盾与构造器
shaders/                       最终画面滤镜及原有 Shader
sounds/                        snd... 音频资源
sprites/                       战斗、UI、弹幕与动画素材
docs/                          当前任务状态、错误记录和验证证据
```

## 3. 数据模型与稳定身份

### 3.1 工程根结构

一个攻击工程包含：

- `format`：固定为 `uteu_attack_editor`；
- `version`：当前为 `25`；
- `next_uid`：下一稳定 UID；
- `name`：工程名；
- `duration`：手动总时长，负数表示自动推导；
- `settings`：编辑器与开发者设置；
- `initialization`：玩家、护盾、HUD、敌人、回合文本、物品、战斗框、GB 默认出生和正式战斗音乐；
- `turns`：逐怪物回合的文本与对话表现；
- `variables`：工程级数字变量；
- `events`：时间轴对象；
- `script_lists`：Workspace 列表和列表项目；
- `resources`：由项目拥有的外部资源登记；当前记录导入音频、敌人贴图/动画和自定义 GB 视觉组。

### 3.2 UID、名称与 Control ID

三种身份不可混用：

- UID：由工程分配，永久唯一。用于存档引用、物品触发、对象读取、瞄准、战斗框顶点和节点连接。普通作者通常不需要手填。
- 名称：作者可读且在工程内保持唯一，用于识别对象。
- Control ID：允许重复，用于把多个运行对象作为一组控制。

脚本目标的真实分组键是“目标类型 + Control ID”。骨头 `A` 与战斗框 `A` 不会因为字符串相同而被同一个控制步骤误伤。排列函数生成的所有成员共享本次函数的 Control ID；成员仍有各自运行身份。

### 3.3 旧存档迁移

`BattleEditor_ProjectNormalize` 在载入和使用数据前补齐缺失字段。新增字段必须有默认值，迁移只修复已知旧默认或旧格式，不覆盖作者明确修改过的数值、颜色、坐标或分组。

当前迁移覆盖的原则包括：

- 旧对象补 UID、唯一名称、Control ID、Transform、动画、裁剪、层级和伤害结构；
- 旧框补形状、半径、多边形顶点 UID、深度和颜色；
- 旧物品补 UID、使用触发与文字声音；
- 旧脚本步骤补等待模式、音效时机、变量读取、控制分类、物理/旋转参数和启用状态；
- 旧组合滤镜拆为同一帧执行的独立滤镜步骤；
- 旧四个骨墙动作迁移为一个骨墙函数加方向字段；
- v17 为控制 Bone 长度补“中心 / 头端固定 / 尾端固定”锚点默认值；旧生成对象保留开关迁移到对应生命周期 `-1`；
- v18 为函数轨迹加入“复制已有对象”和“带动已有对象组”两种来源；起始点局部变量 `X/Y` 表示执行时对象或对象组中心；
- v19 去掉新建函数轨迹继续生成默认 Bone 的 UI 能力；单对象来源必须选择一个正常可实例化的已有对象。v18 及更早未选择模板的默认 Bone 只保留隐藏兼容标志，旧存档仍能读取和运行；
- v20 加入文件夹存档与项目资源登记。旧 JSON 缺少 `resources` 时自动补空结构；载入页可导入旧单文件 JSON，再另存为文件夹存档；
- v21 加入按敌人 UID 管理的角色贴图/动画资源、角色目录和可视化部件编辑字段；
- v22 加入命名 GB 贴图组、本体逐帧动画、三套光束动画和对应场景引用；
- v23 将敌人数据扩展到 15 个并补复制敌人所需的独立 UID、Control ID、资源和行动列表引用；
- v24 加入正式战斗音乐资源与低 FPS 逻辑帧校正开关；旧存档默认不播放音乐且关闭校正；
- 旧 `run_script` 数据可读取但运行时保持惰性，不再通过资源名执行任意 GML；
- 真刀旧数据迁移到当前一次高伤、短动画和宽度预设；
- 老项目的怪物回合框尺寸是作者数据，不会被玩家回合宽框偷偷覆盖。

保存成功后会立即从同一路径读回并重新解析 JSON，避免只因文件句柄成功就报告保存成功。载入会覆盖当前工程，因此 UI 在保存和载入前都要求确认。解析失败会显示错误且不把损坏数据当成新工程。

### 3.4 可移植文件夹存档

Windows 桌面版把 `save/` 放在 Runner 使用的 `.win` 或发布版 EXE 数据目录同级。存档名先过滤 Windows 非法文件名字符，再作为文件夹名使用。结构如下：

```text
save/
|-- 存档名称/
|   |-- project.json
|   |-- textures/
|   |-- audio/
|   `-- _backup/
|       `-- project.json
|-- _runtime/
|   |-- current/
|   |   |-- project.json
|   |   |-- textures/
|   |   `-- audio/
|   `-- undo_load/
|       |-- project.json
|       |-- textures/
|       `-- audio/
`-- _state/
    `-- active.txt
```

- 文件选择器导入图片或音频时，资源立即暂存进 `_runtime/current`，不再依赖原始素材留在原路径。保存命名存档时会复制到该存档自己的 `textures/` 或 `audio/`，并把 JSON 改写为相对路径。
- 覆盖同名存档前，旧 `project.json` 留在 `_backup`。资源文件使用不覆盖的唯一名称，因此旧 JSON 引用的旧资源仍存在。“撤销保存”恢复这一版后即消耗本次机会。
- 载入或导入另一项目之前，当前内存工程完整写入 `_runtime/undo_load`。“复原载入”恢复它后即消耗本次机会。
- `_runtime/current` 是不属于任何命名存档的编辑现场。节点拖动、连接、新增或删除只标记现场已修改；输入结束并连续空闲约 12 帧后才比较一次内容并写入 JSON。恢复快照引用已经暂存的资源，不会像正式保存那样重新遍历、复制和打包全部贴图/音频；Draw 和持续拖动的 Step 都不序列化或写盘。
- 成功保存或载入会把该存档记为当前战斗读取项。若 `active.txt` 缺失或目标被删除，系统按 `project.json` 修改时间选择最近编辑的有效存档并写回一次。
- 正常从标题进入战斗时会在过场/切换房间前优先读取 `_runtime/current`，因此尚未再次正式保存的最新编辑也会生效。整个游戏的“设置”页仍提供“战斗读取存档”；用左右键或 Z/Enter 明确选择某个文件夹存档后，会记录为覆盖来源并读取该存档。再次进入编辑器并产生新的 `current` 恢复现场后，来源自动回到最新编辑现场。两者都无有效数据时才回退到新工程。

## 4. 默认工程

默认工程不是演示弹幕：`events` 和 `script_lists` 初始为空。它保留可运行战斗所需的初始化数据：

- 玩家名 `hi175570`；
- LV 25，ATK 10，DEF 10；
- 当前 HP、当前 HP 上限、完整 HP 上限均为 114514；
- 当前护盾、当前护盾上限、完整护盾上限均为 100；
- 玩家回合框中心 `(320,320)`，上/下 65、左/右 283；
- 怪物回合主框中心 `(320,320)`，上/下/左/右均为 65，即 `130 × 130` 正方形；
- 主框 UID 1、Control ID `main_board`；
- 默认回合文本 `* 第一回合`；
- 默认加入一个 Sans 敌人；
- 默认 GB 从画面正上方外、距离 800、初始角 270°；
- 默认不播放战斗音乐；
- 默认物品为 8 项，可继续增至 114 项。

玩家/菜单回合使用玩家回合框；真正进入怪物回合时使用怪物回合框。选择主框或进入半播放状态会显示怪物回合的脚本起点，不应在普通非播放 Step 中持续把脚本结果重写成初始化正方形。怪物回合结束进入 `BOARD_RESETTING` 时，代码必须复原玩家回合长方形。普通矩形若刚好旋转了 90° 的整数倍，会先把上/下/左/右半径作等价换位并把角度规范到 0°；画面几何保持不变，因此复原动画不会先多做一次肉眼可见的反向旋转。圆形、三角形与多边形则继续使用轮廓变形回到玩家框。

## 5. 编辑器界面与绘制层级

### 5.1 顶栏

游戏设置中的“窗口缩放”提供 100%、125%、150%、175%、200% 和适应屏幕。缩放同时作用于游戏和编辑器，保存在现有全局设置中；只调整窗口客户区，不放大相机视野、不改 640×480 GUI 或对象坐标。屏幕放不下时等比缩小至可容纳大小。进入/退出编辑器不会重置比例，F4 全屏独立，退出全屏恢复窗口比例。

顶栏依次提供：初始化、新对象、脚本、播放、存档、退出、开发者；公式框聚焦时显示“插入变量”，最右侧为 `?` 教学。“存档”打开统一弹层，再从其中新建存档、保存当前、载入存档、撤销上次保存或复原上次载入，不在顶栏并列放置两套入口。

进入编辑器时默认打开“新对象”。面板顶部始终保留“分类”下拉；内建攻击、战斗框等不是无法返回的二级分页，切换分类只替换下方可创建项，不关闭面板，也不要求重新点击“新对象”。点击“脚本”直接进入沉浸式 Workspace，顶部工具栏及其点击区域同时隐藏；Esc 收起 Workspace 后顶栏恢复，并仍保持选中“脚本”。可再次 Esc 返回，也可切换其他标签。可见顶栏最后绘制，平移、缩放、列表拖动和节点连接不能盖住它，也不能让视觉位置与点击区域错位。

### 5.2 面板与输入

- 初始化、新对象属性和长参数表使用卷动区域；参数增加时扩展内容高度，不把关键文字压成大量 `...`。
- 每个参数拥有一个具名控件。数字或公式使用输入框，枚举使用下拉，布尔使用开关。
- 单行输入框在编辑期间不预先限制字符：可留空、粘贴任意文字，并用 Left/Right/Home/End 移动真实游标、Backspace/Delete 在游标处删除。字段只在 Enter 或点击外部时按自身类型解析；空白或无效的数值编辑点击外部会恢复原值、释放焦点，并继续执行同一次列表/按钮点击。
- 下拉入口统一绘制项目内的向下箭头 Sprite，不依赖当前字体是否包含箭头字符。对象 Inspector 的标题、层级和颜色各有明确区域；层级独占标题下方一行，视觉颜色再独占一行并以宽色块显示“跟随伤害 / 自定义”，不允许按钮覆盖对象标题，也不截断“框内 / 框外 / 框下”。
- 内部为兼容旧存档仍可用分号序列化参数，但 UI 永远不暴露一串神秘数字。
- 数字框允许编辑期间暂时为空；按 Enter 或点到别处时才提交。无效或半截公式不会把模型改成 0。
- 下拉在点到外部后收起；长菜单可滚动。
- 浅灰文字只用于持续有效的字段说明、操作提示或空状态，不显示“本次新增”“已独立化”之类只对某次更新有意义的公告。

## 6. 初始化系统

### 6.1 玩家与 HUD

可以编辑名称、LV、ATK、DEF、当前 HP、当前 HP 上限、完整 HP 上限、当前护盾、当前护盾上限、完整护盾上限，以及 HP 标签、血条、KR、数字、护盾、灵魂上方数值的显示开关。护盾可放在血条下方或血条右侧。

当前 HP 不超过当前上限，当前上限不超过完整上限；护盾同理。每次应用初始化会清理旧预览残留的 KR。HUD、名字、LV、血量组、四个按钮和每一个 FIGHT/ACT/ITEM/MERCY 按钮都是可控制的系统目标，但不能被排列函数复制。

### 6.2 回合文本、敌人台词与声音

`turns` 按怪物回合编号保存回合框文本、敌人气泡台词、两者字体、两者打字声音、气泡模板、气泡相对敌人根节点的 X/Y 偏移。

气泡模板有宽气泡尖角向左/右、小气泡尖角向左/右和无框短句。文字声音有无声、默认文字音、打字机音、Sans、Toriel。

时间轴 `0:00.0` 定义为下一怪物回合中敌人台词和战斗框准备完成、攻击正式开始的时刻。灵魂在台词结束前保持红魂；目标灵魂模式在 `TURN_START` 才应用。

### 6.3 敌人

最多创建 15 个敌人。每个敌人都能显示、保存并接受 Workspace 脚本控制；由于原版 FIGHT/ACT 目标菜单没有滚动，只有前 3 个属于可被玩家精确选择的原生目标槽，第 4～15 个不会出现在目标菜单。像 Ending Time Octet 这类需要同时展示许多角色的战斗可以建立全部角色，但回合制 FIGHT/ACT 仍应把需要玩家选择的目标放在前三位。

“复制敌人”会复制完整角色数据、动作选项、角色专属贴图/动画资源和对应的行动项目 Workspace 列表，同时为敌人、动作、资源、脚本列表和步骤分配独立 UID，并生成独立名称、Control ID 与角色资源目录。副本不会与原角色共享会被编辑覆盖的身份。

“新增空白敌人”建立真正的空角色，不复制当前敌人；“恢复默认敌人”则在当前位置重新建立默认 Sans。新增和复制都会寻找附近可见空位，避免多个角色完全重叠而被误判为没有生成。角色显示名称与角色资源目录同名并一起重命名，Workspace 和动画引用依靠隐藏 UID，不会因改名断开。

每个敌人包含 UID、唯一名称、Control ID、整体中心、缩放、横向摆动公式、身体/头部 Y 摆动公式、身体/头/脸/左手/右手/腿六个部件、部件资源和局部偏移，以及四个蓝魂重力方向的可选动画脚本。

“可视化编辑”会打开独立敌人画布。作者可选择 Root 或六个部件并直接拖动，右侧面板同时提供精确的整体/局部坐标、缩放、Sprite、资源原点与动画参数。静态图和逐帧动画都从当前角色自己的资源目录读取；可新建动画、导入或删除帧、调整 FPS 与循环并播放预览。画布负责空间摆放，属性栏负责精确数值，不要求手填全部局部坐标。

重力动画脚本只收到敌人索引、敌人数据和重力方向，不用这个通道控制框或弹幕。未指定脚本时敌人不会因蓝魂切换做神秘甩手动作。

### 6.4 战斗音乐

“敌人与回合 → 战斗音乐”从引擎实际存在的全部 GameMaker 音频资源和当前存档已导入的音频中选择正式 BGM；它不套用普通音效选择器的 `snd...` 名称过滤，所以 `shop_theme` 或以后加入的 `bgm...` 也能直接选择。“无”是明确的不播放状态。导入会复用项目 `audio/` 资源归档，选择器旁可用同一个播放/停止按钮试听，整首音乐不会被预览器擅自截断。

播放同步方式有两种。正常播放让音频按真实时间前进；“低 FPS 音频校正”让同一个 BGM 槽位的播放位置跟随 `GAME_FPS` 逻辑时间。校正每个 Step 累加 `global.delta_time_factor`，仅当原生音频位置与期望位置相差至少 `0.02` 秒时调用 `audio_sound_set_track_position`，所以掉帧时音乐随游戏变慢但不改变音高，也不会每帧无条件 seek。两种方式都继续使用既有 BGM 音量、暂停、停止、循环和淡入淡出系统，不建立第二套播放器；回合制、生存战或混合战斗都可独立选择。

### 6.5 物品

物品栏最多 114 项。每项包含稳定 UID、名称、回血量、可分页食用文本、文本声音和使用触发身份。列表新增或删除后立即刷新；第 9 项以后仍显示名称且可使用。

物品使用时显示自己的文本，执行回血和音效，以 UID 触发 Workspace 列表，然后从库存移除。若深绿伤害降低过当前 HP 上限，治疗量的 25% 先修复上限，剩余部分再恢复当前 HP。

## 7. 新对象与时间轴事件

### 7.1 对象分类

“新对象”的分类下拉提供：

- 内建攻击：骨头、骨刺、GB、真刀、斩击、友谊颗粒、火球、长矛、三叉戟、刀子、3D 骨、4D 骨；
- 自定义弹幕；
- 装饰；
- 战斗框；
- 打字机；
- 蓝魂平台。

分类选择器始终位于面板顶部。选择分类后，下方显示该类的预设或创建入口；选择具体对象后才进入画布放置。Workspace 的“创建对象”步骤复用同一套分类、预设、事件数据构造器与运行生成器，但没有画布放置状态：作者选择对象后直接填写 X/Y、角度、寿命、尺寸、伤害颜色、层级和 Control ID。

友谊颗粒和火球为内建两帧循环动画；长矛、三叉戟和刀子是独立预设。三叉戟的新建默认缩放为 `1 × 1`，不再偷偷套用缩小倍率。自定义弹幕可读取内建 Sprite 或文件，支持单帧、帧列表或横向 Strip、FPS 与循环。装饰拥有变换、颜色、透明度、动画和层级，但不进入伤害判定。

### 7.2 通用事件字段

适用对象共享 UID、名称、Control ID、出生帧、存活帧、X/Y、角度、X/Y 缩放、透明度、颜色、Tween、Ease、框内/框外/框下层级、裁剪来源、裁剪框 UID、“不可见部分是否碰撞”、伤害类型、伤害值、回血值，以及视觉颜色是否跟随伤害颜色。

生命周期 UI 分为“本回合一直存在”和“指定存活帧数”；前者内部仍保存为 `duration=-1` 以兼容旧存档，但用户不必记忆这个隐藏数值。框内对象受 Board 裁剪；框外对象不裁剪；框下对象位于框下方并不造成碰撞伤害。

### 7.3 场景选择、拖动与分组

- 单击选择一个对象；350ms 内再次双击同一对象，选择同类型且同 Control ID 的整组。
- 组拖动为所有成员增加相同位移；组旋转以双击主对象为世界坐标原点，主对象位置不动，其他成员绕它转，所有成员自身角度同步变化。
- 跟随框的骨头会换算回局部坐标；GB 的目标方向和自定义出生点也随组旋转更新。
- 单字段编辑只同步该字段，不覆盖其他字段。
- 拖动保留鼠标抓取偏移，不先跳到中心；普通对象可拖到 HUD 下方或画面外，战斗框仍有专用边界。
- 真刀和斩击的整条可见刀线都是命中测试与拖动区域。
- Bone、GB、平台、三叉戟及其他 Sprite 对象以画面上实际绘制的完整贴图矩形作为选择与拖动区域（包含透明边距和当前缩放/旋转），只为极小贴图补最低容错范围，不再要求命中隐藏中心点。
- 鼠标滚轮每格旋转 1°，Ctrl 为 5°，Shift 为 10°。

## 8. 战斗框系统

### 8.1 MAIN、ADD、SUBTRACT

MAIN 是唯一主框；ADD 增加活动区域；SUBTRACT 从结果挖洞。组合顺序是主框与全部加框形成并集，再应用全部减框。减框显示真实后方画面，不用黑色矩形遮盖。

框内遮罩颜色是独立于边框颜色的战斗框控制动作。它使用带色块的下拉菜单，可直接选择默认黑色、七种灵魂色或九种攻击色，并沿用控制步骤的持续时间、Tween 与 Ease；它只改变框内 Surface 的底色，不改边框、攻击类型或灵魂模式。

边框沿最终布尔结果判断，只在一侧可活动、另一侧不可活动时绘制，所以重叠加框不留下内部白线。边缘固定 5px 屏幕宽度，不随拉伸变细，也不产生楔块。

### 8.2 形状与顶点

支持矩形、椭圆、正三角形和任意多边形。规则形状只保存中心、规则尺寸和角度；只有单独拖顶点才转 Polygon。多边形每个顶点有永久 UID，脚本引用 UID 而非数组下标，因此插点、删点后不会错控。

右键可新增顶点并强制切换形状。主框必须通过“选择主框”或明确框操作选择；选中主框会进入怪物回合 `0:00.0` 的冻结预览。

### 8.3 脚本平滑变形

“平滑切换战斗框形状”包含目标战斗框 Control ID、目标形状、过渡帧、Tween、Ease。运行时把源/目标轮廓按周长重采样为 64 个点，从相同上方起点和绕向逐点插值，同时更新三角划分、填充、碰撞与边缘。持续时间最少 2 帧；中途收到新变形会从当时可见轮廓接管。

手动形状编辑仍立即生效；脚本运行时的形状改变必须可见地平滑过渡。

## 9. 单体攻击对象

### 9.1 骨头

骨头支持位置、角度、长度、速度、自转、寿命、层级、伤害/回血、跟随指定战斗框、局部坐标、按 UID 瞄准、一次或持续瞄准、沿瞄准方向移动、绿魂盾格挡与格挡销毁。“锁定一次”会在执行帧保存目标方向，随后沿直线越过目标当时的位置；只有“持续追踪”才会每帧重新转向。骨墙使用 Bone 时目标点表示骨头头部，而非 Sprite 中心。

### 9.2 GB

GB 场景点表示目标位置。出生可继承全局、使用自定义坐标、画面中心、画面八方向或相对目标八方向；屏幕外距离固定 800。可配置起始/目标角、X/Y 缩放、移动/发射前等待/光束帧、Tween/Ease、伤害、层级与真实/假动画/假掉落模式。内置 GB 的本体发射会依次显示六帧，预备动作沿素材横轴压缩；风车批量生成的每个 GB 复用同一套六帧本体和按伤害类型选择的光束。光束宽度沿用 UTE 每帧推进 0.25 弧度的呼吸节奏，约 25 帧完成一轮，不把 Scratch 同一帧内的循环误当成六帧高频闪动。

初始化的“GB 贴图”子页管理命名视觉组。原版 UTE GB 永远只读并作为无选择时的默认；新组以素材包的 6 帧完整 Gaster Blaster 本体和基础/橙色/蓝色三套光束起步。本体与每套光束都能独立增删、替换、重排任意数量的帧，并保存帧间隔、素材朝向、本体原点、光束发射点、宽度、展开比例、呼吸幅度与判定内缩。素材朝向只说明图片本身朝哪边，攻击角度仍是世界中的发射方向。只有存在自定义组时，创建 GB 才增加组选择器。

“发射预览”默认静止，按一次后只演示一次朝右的飞入、开口、直线光束、收束。真实 GB 与假动画 GB 在执行后只循环最后两张张嘴帧；假动画 GB 不产生光束并向下掉落，假掉落 GB 则保持闭口，播放受击音效后直接掉落。创建对象和场景中的作者预览始终固定闭口、不闪，并按素材朝向换算成与运行时相同的世界发射角。

GB 通用偏移按原 Scratch 实现包含固定退出方向、初始速度、每帧速度变化和独立的本体旋转速度，并在开口发射时开始。退出方向可选“自动沿 GB 后方”（当前发射角 + 180°）或自定义绝对角度；每帧速度变化为 0 时匀速，负值会减速、停下和反向。旧版误加的“路径弯曲角速”字段只为载入兼容保留，不再参与运行或出现在新 UI；若要分段改变方向，使用控制脚本在对应时刻改退出方向。

真实光束按当前视野绘制无限数学射线切片，不依赖有限 Sprite 长度。结束前必须收窄到 0 才允许清理。假 GB 不生成真实光束；掉落模式先上弹再受重力离场。

### 9.3 斩击

斩击有警告与攻击阶段，可配置阶段时间、宽度、攻击前/后方向、速度、加速度、曲线角速度，以及不旋转/持续转速/曲线转目标角三种旋转模式。每段有独立目标角、旋转时间、Tween、Ease。视觉宽度和碰撞宽度分离。

### 9.4 真刀

真刀保持一次高伤模型，不是帧伤：默认警告 12 帧、攻击 18 帧、最窄宽 7、最大宽 40、伤害 55、专属无敌 30 帧；伤害和无敌帧可配置。

动画只有一次“出现 → 变宽 → 立即收窄淡出”。100 HP 受到 55 后变 45 HP，瞬间 KR 绝对端点仍为 100；10 HP 时直接扣 9，剩余 46 加到 KR。真刀之间共享专属冷却，但可与骨头叠加。

完整格挡需要 25 当前护盾；不足时：`剩余伤害 = round(伤害 × (1 - 已消耗护盾 / 25))`。例如 10 护盾格挡 55 后剩 33，不扣护盾上限。

### 9.5 3D 骨、4D 骨与平台

3D/4D 直接复用已有构造器。3D 暴露中心、出生/寿命、六种立体形状、XYZ 角和转速、XYZ 尺寸、水平/垂直速度、世界 Z、透视、边缘、伤害与层级。4D 额外暴露 XW/YW/ZW 角与转速、W 尺寸和 4D 透视。透视距离最少 32，边缘留白不小于 0。

蓝魂平台使用 Nine Slice 端帽/中段和同步碰撞宽度，不用拉伸整张贴图。可设置中心、角度、宽度、出生/寿命、水平/垂直速度、层级和反弹。绿色会带着玩家移动；紫色可站立但不带玩家。

## 10. 伤害、颜色、KR 与护盾

| 编号 | 名称 | RGB | 默认语义 |
| --- | --- | --- | --- |
| 0 | 白色 | 255,255,255 | 普通伤害 |
| 1 | 蓝色 | 20,196,255 | 玩家移动时伤害 |
| 2 | 橙色 | 248,148,29 | 玩家静止时伤害 |
| 3 | 亮绿色 | 0,255,0 | 回血并销毁 |
| 4 | 黄色 | 255,255,0 | 5/3，可配置黄魂射击 |
| 5 | 深绿色 | 0,96,32 | 减当前 HP 上限 |
| 6 | 红色 | 255,0,0 | 秒杀 |
| 7 | 紫色占用 | 75,0,130 | 不立即扣血；累计紫色占用条，最多 40，等待下一次其他颜色真正造成伤害时一并结算；该结算可把 HP 降到 0。回血照常增加 HP，但每 2 点治疗量只能抵消 1 点紫色占用；HUD 以同一条缓动曲线同步显示黄色增长与紫色消退 |
| 8 | 深蓝 X 防伤 | 20,32,160 | 接触判定发生时按住 X 可使这次攻击不造成伤害 |

白/蓝/橙/深蓝默认 HP/KR 端点包为 2/1；紫色默认累计 1 点占用值，累计值按普通伤害公式结算但不立即改动 HP、KR 或 HP 上限。紫色段使用与紫色攻击完全相同的 `75,0,130`，从黄色当前 HP 的右端向左增长并覆盖相同宽度的黄色区域；KR 仍位于当前 HP 端点之后。只有另一个颜色的攻击通过自身条件、护盾和无敌锁并实际造成伤害，才会在同一次伤害包中清空并结算占用值；结算时紫色段会先随机向上弹出，再带水平漂移、重力和随机角速度作为独立色块掉落。回血按 `floor(治疗量 / 2)` 抵消紫色：20 点治疗最多清除 10 点紫色，奇数治疗量不足 2 的余数不清除半点紫色。亮绿默认回血 10；深绿减上限 1；红色秒杀。

新建攻击的显示颜色默认启用“固定模板”，模板初值沿用该攻击的设计颜色；真刀仍固定为红色视觉，但其伤害机制不会因此变成红色秒杀。对象 Inspector 与 Workspace 创建表单都使用同一交互：勾选“固定模板”时显示颜色模板下拉，取消勾选时才开放自由调色板。伤害判定类型始终由独立下拉选择，显示颜色不会冒充碰撞规则；旧存档已经保存的跟随、固定或自由颜色模式保持原值。

灵魂可见贴图不缩小，但伤害碰撞统一使用中心 `5 × 5` 判定框；普通 Sprite 遮罩碰撞和 GB 光束的手写线段判定共用同一尺寸。

伤害只应用一次 `DEF/5`，不使用高 HP 伤害奖励。UTE 保存 pending KR，AllScript 保存绝对端点：`绝对 KR 端点 = HP + pending KR`。DEF 作用 HP 端点后按比例保留两端有符号差，不能把 2/1 防成 1/1。HP 到 1 后继续消费剩余端点；KR 每 0.25 秒减少 1。

伤害冷却分普通、蓝、橙、真刀通道。蓝与橙可叠，真刀与骨头可叠；同色接触和多把真刀不会每 Step 重复结算。

## 11. 文本、标记、字体与输入

回合文本、敌人气泡、物品文本和场景打字机共用 TextTyper。打字机支持位置、角度、缩放、透明度、字体、文字、速度、深度、层级、分页确认和自动换页延迟。

文本窗口支持鼠标光标、中间插入、方向键、Backspace/Delete、Enter 换行、`<br>`、`<page>`、Z/Enter 确认与 X 加速。标记包括 `<wait=秒>`、`<color=#RRGGBB[AA]>`、`<gradient=#色,#色>`、`<shake>`、`<glitch>`、`<float>`、`<rotate=角度>`、`<cycle>`、`<page>`、`<br>`；会检查未知标签、Hex、未闭合与嵌套错误。

字体策略刻意收窄：普通文字和符号使用当前游戏字体；用户选择拉丁字体时，中文只回退到项目自己的 CJK 字体；仅当码点实际存在于 Android/Gboard 风格彩色 Emoji 图集时才改画 Emoji。测宽与绘制共享同一选择，普通字符会先快速排除，不再逐字扫描整张 Emoji 映射。教学缓存布局并只绘制可见行。普通回合文本、敌人气泡、物品文字、自由打字机和死亡文本使用同一字体组；Windows 直接输入偶尔产生的 UTF-16 代理对会在输入、旧存档迁移和 `text_typer` 接收文本时合并成真正的补充平面码点，再交给同一彩色 Emoji 图集。该修复已进入代码与存档迁移，视觉输入仍需 Runner 验证。

## 12. Workspace 画布与节点设计

Workspace 展开/收起只是编辑器视图状态，不创建新运行时或序列化第二套数据。往返保留当前列表/项目、画布平移及缩放；输入框、下拉、拖放和节点连线优先消耗 Esc，一次按键只取消一层。切换到其他标签后，Esc 不会擅自重新打开 Workspace。收起不调用退出游戏或换房间逻辑。公式帮助只在 Workspace 右上角，重复点击可收起；初始化/脚本顶栏不再显示它。帮助内容按实际字体宽度换行，面板高度包含标题和底部留白。

右侧属性面板采用圆角暗色卡片、独立标题与柔和边框；按钮、输入框、展开下拉沿用同一风格。保留现有字段、命中位置和整个面板的滑入动画，不改变参数语义，不把文字颜色绑定到选中边框。

Workspace 左侧有通过小箭头图标收放的积木侧栏，整个面板缓动滑入/滑出，分为事件头与普通积木，两类均可直接拖到画布。普通积木落在空白处只形成不执行的游离串，必须另外拖入事件头才成为可执行列表。列表头带动整串；从中间拖动项目则带走该项及后续串，可在原列表或其他串中吸附插入。拖动激活后只在鼠标旁显示被拿起的段，原位只画剩余前缀，不出现两份；松手才提交结构变化，Esc 或右键取消立即恢复原位且不会改动数据。空白拖动平移，Ctrl+滚轮围绕鼠标缩放；节点连接继续以列表 UID 引用事件头。右键提供复制、剪下、贴上、删除及项目启用切换，不再是创建入口。

拼接后使用整串圆角外轮廓，不逐项绘制分隔边。循环范围直接改变原有外边框对应部分的颜色，边线只提交一次，不叠加第二层矩形，也不改内部分界，文本色不继承选中边框或循环色。循环范围只在编辑提交后重新缓存，不在每帧重新扫描。游离串仍存入原 `script_lists`，以 `entry_kind = -1` 标识；旧事件枚举编号不变。自动触发、手动运行、节点启动和回合时长估算都排除游离串。拆分、重接保留步骤 UID 和参数；删除空游离容器不删除移动后的步骤。当前回归范围见 `docs/WORKSPACE_DRAG_BATCH.md`。

节点连接保存目标列表 UID，并用 20 段三次贝塞尔曲线绘制。控制点只沿 X 弯曲，距离为 `max(28, abs(dx) × 0.42)`；这是固定设计，没有用户开关。

列表触发有游戏开始、怪物回合、计时器帧、玩家受伤、指定 UID 物品使用、指定 UID 敌人行动项目和脚本入口。物品与行动项目都用稳定 UID 绑定，改名和重名不会串到别项；单列表运行不会额外触发游戏开始或当前回合列表。

节点颜色：控制对象蓝、内建函数橙、画面/滤镜紫、音效粉、变量/读取青绿、条件红、等待灰紫、循环黄褐、连接青蓝、旧脚本灰；选中统一黄边。颜色只服务可读性。

除等待外，连续项目与有限循环的瞬时轮次都在同一逻辑帧提交并并行执行，不设可见的每帧项目数节流。节点连接新建的列表状态从下一帧开始，因此自连接不会在同一调用栈无限递归。

## 13. Workspace 项目完整语义

### 13.1 控制对象

选择目标大类、动态目标、属性分类和属性。目标大类为攻击对象、战斗框、装饰与文字、敌人、玩家与规则、战斗界面。

通用动作有绝对/相对位置、绕中心的世界轨道旋转、方向/速度/加速度/曲线/自转物理、“朝向 / 追踪目标”，以及带持续帧和 Tween/Ease 的属性动画。“朝向 / 追踪目标”只按目标是否具备世界位置开放，不绑定 Bone，并明确分为“仅面朝目标”“面朝并向目标移动”“只向目标方向移动”三种行为；方向更新另选“执行时锁定一次”或“持续追踪目标”。锁定一次保存执行帧方向并沿该方向直线飞行，不会抵达旧目标点后掉头；持续追踪才每帧重算方向。控制来源明确分成“控制原件”和“复制后控制”，后者另填副本 Control ID，系统对象不会进入可复制来源。控制 Bone 长度时额外选择“长度锚点”：中心让两端一起伸缩；头端固定时只让尾端移动；尾端固定时只让头端移动。头尾按 Bone 自身局部角度定义，横向、90°、270°或任意旋转都使用同一规则，不要求作者换算屏幕方向。

移动、轨道、物理和追踪移动都可以附加前置警告。警告线与骨墙警告框使用 Undertale 风格红色/黄色交替闪烁；警告阶段没有碰撞，结束后才执行控制。追踪移动使用自动朝向时，警告线默认指向所选目标，也可切换为自定义角度。

属性能力矩阵：

- Bone：位置、轨道、物理、角度、自转、长度、速度、寿命、伤害、层级、跟随、瞄准和绿盾行为。
- GB：位置、物理、角度、缩放、瞄准、各阶段时间、真假模式、偏移与伤害。
- Slash/True Knife：位置、轨道、物理、角度、阶段运动、旋转、伤害；真刀额外有专属无敌帧。
- 3D/4D：位置、轨道、物理、多维角度/转速/尺寸、透视、边缘、寿命和伤害。
- Platform：位置、轨道、物理、角度、宽度、速度、寿命、类型、反弹。
- Board：位置、轨道、物理、角度、自转、形状、宽高/半径/三角尺寸、颜色、加减框和顶点。
- Decoration/Sprite Hazard/Typewriter/Enemy：只公开各自确实具备的变换、外观、文字或伤害能力。
- Player/HUD/Buttons/Soul：公开数值、显示、变换和模式，不作为复制模板。

灵魂模式下拉为红、蓝、绿、紫、黄、橙、青。蓝魂方向下拉为上、下、左、右；“同时施加重力甩动”是独立勾选框。只改方向不会强制甩动，每回合结束恢复红魂。

#### Workspace 创建对象

“创建对象”是瞬时 Workspace 项目，不是画布工具。分类下拉与“新对象”一致，具体对象下拉覆盖内建攻击、自定义弹幕、装饰、加减框、打字机和蓝魂平台；选完后必须直接填写 X/Y 等参数，不会切回场景、等待鼠标点击或进入拖放模式。

普通对象继续由 `BattleEditor_New...` 数据构造器建立，并统一送入 `BattleEditor_SpawnEvent`；加框和减框使用现有 Frame/Board 路径。除战斗框外，新建的 Workspace 对象默认跟随主框，表单可改选任意加框/减框；后续“控制对象 > 启用跟随”会从创建数据读取当前状态，并能解除、重新开启或改选目标框。旧存档缺少字段时保持原先不跟随，避免迁移后整场攻击突然换坐标系。创建结果使用作者填写的 Control ID，立即进入原对象组选单并标记 `[运行时]`，因此后续控制对象步骤不需要另一套选择或运行逻辑。数值框仍支持公式，生命周期 `-1` 表示本回合持续。

敌人的“说话”控制可选“自动打字并继续”或“Z/X 手动推进”。手动模式保留 X 加速打印、Z 确认关闭，并默认勾选“等待气泡结束再继续”，因此同列表后续项目不会在台词尚未确认时启动；取消勾选可让气泡与后续脚本并行，自动模式也可按同一开关决定是否等待打字完成。

### 13.2 等待

等待模式下拉：

- 固定帧数：从当前列表时间点等待作者填写的帧数，已启动动作继续并行运行；
- 等上一个步骤执行完：先等待当前并行块中最长动作完成，再追加“完成后额外等待”的帧数。节点连接本身为零耗时控制流，不会冒充上一动作；若 A 在动作后连接到 B，B 开头使用此等待模式时，会继承并等待 A 中连接前的实际动作。

等待只暂停该列表，不阻塞游戏主线程。等待的结束音效在等待完成时触发。

### 13.3 内建排列与构造函数

所有数值均为具名公式框；枚举为下拉；布尔为开关。

- 椭圆旋转阵：中心 X/Y 与半径 X/Y 分别成组显示；数量、起始角、每帧角步、朝向偏移、长度、颜色和层级保留独立控件。进场行按“时间、Tween、Ease”排列，之后是维持，再是“退场时间、Tween、Ease”，而不是把两段曲线堆在面板末尾。默认 Bone 的半径落在朝向中心的视觉内端，实例原点按当帧真实可见长度反算到圈外，因此相同半径、不同长度必须得到完全相同的中间空圈。正进场从外到内，正退场从内到外；负值才使用中心收放。
- 波浪阵：排列中心、横/纵排列、覆盖范围、对象数量、长度、自身摆动半径、正弦速度、寿命、颜色、层级、ID、模板。横排成员固定各自的 X 基准并自行上下摆动，纵排成员固定各自的 Y 基准并自行左右摆动；成员之间带相位差，单个成员只是走正弦路径，多个成员才形成波浪。它不生成通道。
- 长廊：横/纵移动、起点、生成点数量、间距、通道半宽、长度、生成中心最小/最大值、每点正弦相位增量、前进速度、寿命、颜色、层级、ID、模板。每个生成点产生通道两侧的一对成员；正弦只决定这一对出生时的通道中心，成员生成后不会继续横向摆动，只沿长廊前进方向移动。最小值等于最大值时就是直线长廊。
- 物理散射：中心、数量、X/Y/角动量/长度各自最小最大、寿命、颜色、层级、ID、模板。初值从可见范围取得，之后按固定重力 0.3、X 阻力 0.01、角阻力 0.05 运行。相同端点即固定值。两端全整数则整数随机；有小数则按更多小数位的精度离散抽样，不设人为位数上限。
- GB 风车：中心、椭圆半径、数量、起始角、角步长、朝向偏移、生成间隔、实际发射间隔、发射前等待、光束、进场、颜色、ID。它按角度依次定位/生成/发射，不维护持续旋转环；间隔 0 表示同时。生成间隔只决定对象何时出现，实际发射间隔直接表示相邻两只 GB 发射相差的帧数，不会再与生成间隔相加；生成速度不够时只把整组首次发射向后平移。
- 3D/4D：直接包装第 9.5 节构造器。
- 函数轨迹：以“精确起始点 X/Y + X(自变量)/Y(自变量) 位移公式”定义参数曲线，公式位移会减去自变量起始值处的结果，所以第一个采样点严格等于起始点。来源只有“复制已有对象”和“带动已有对象组”：前者按稳定 UID 选择一个正常可实例化对象，深复制其作者属性并只让副本进入轨迹，原对象不动；后者从原控制组选单选择 Control ID 与对象类型，保存每个成员相对组中心的偏移后整体平移，不把成员压到同一点，也不复制或销毁原组。起始点输入大写 `X`、`Y` 时，单对象复制取原对象执行瞬间的位置，已有组取执行瞬间的组中心。配置仍包含局部自变量名称与起止值、移动帧、生成副本的长度/颜色/层级、固定角度或路径切线；公式还可使用 `progress`（0~1）。Inspector 的“预览轨迹”继续使用同一个运行采样器并只在参数改变后重算。
- 平滑框形状：见第 8.3 节。

骨墙只有一个函数。方向表示运动方向：上从下进、下从上进、左从右进、右从左进。单方向显示目标 X/Y 与目标高度；上下/左右/四方向显示中心 X/Y 与中心半径。四方向是正方形快捷方式。宽度是每边成员数，偶数时中心在中间两根之间。Bone 的目标点为头部；起始点沿反方向偏移目标高度，进入、停留、再原路退出。它还支持间距、长度、速度、停留、颜色、层级、彼此独立的进/退场 Tween/Ease、ID 和模板。

模板函数只复制普通可实例化事件，排除 GB 和系统对象。副本是作者数据的深复制，保留模板的贴图、颜色、长度及其他公开属性；排列算法只接管它需要的位置、朝向和本次 Control ID，不修改模板原件，也不会把原件本身加入阵列。

直接控制的目标选单把两种能力明确分开：普通项只显示 `名称 · 数量 · ID`，控制构造器产生的实际对象；算法项显示简短的 `旋转轨节点 · ID`、`波浪节点 · ID`、`长廊节点 · ID`、`物理发射节点 · ID`、`函数轨迹节点 · ID`、`GB 风车节点 · ID` 或 `骨墙节点 · ID`。成员组的世界移动会转交给所属算法中心，避免下一帧被轨迹写回；控制节点额外公开自身真正具备的参数，例如旋转轨/GB 风车半径、波浪排列范围/摆幅/速度和骨墙目标距离。说明文字不再占用目标名称宽度。

“直接”与“复制”是两个独立标签。直接模式只列真实 Control ID、系统对象和上述运行时控制节点；复制模式只列可实例化的作者场景对象来源，并显示 `复制来源：对象名 | ID`。系统对象和运行时控制节点不会进入复制列表。复制结果仍取得独立递增 Control ID，原件保留。

对象组选单同时列出作者放置组和内建构造器将要生成的组。后者继续使用同一套 Control ID/目标类型选择逻辑，只在数量后标记 `[运行时]`；不另建 Runtime Groups 页面，也不把临时组序列化成场景对象。显示数量按真实构造规模计算，例如旋转圈与波浪阵为对象数量、长廊为生成点数量的两倍、四方向骨墙为每边宽度的四倍。

生成函数不再提供与生命周期重复的“结束后保留”开关。有限生命周期到时执行该算法已有的退场并清理；生命周期 `-1` 表示持续到本回合统一清理。旋转阵或骨墙使用 `-1` 时不进入退场阶段。v16 及更早存档若旧开关为开启，载入时会把对应维持/存活字段迁移成 `-1`，随后清除旧开关状态。

### 13.4 画面、镜头与滤镜

独立动作包括：镜头中心/X-Y 缩放/旋转/过渡，正弦晃屏，带随机方向与拖影开关的震动，色相、饱和度、亮度、对比度、灰度、反色、故障、色差、扫描线、画面波浪、暗角、像素化、Kawase 模糊，以及重置镜头/效果。预览捕获并恢复原镜头；最终 Shader 处理输出 Surface，不改房间相机视野补缩放。

### 13.5 音频

音效下拉直接枚举真实 `snd...` 资源。每个音效选择器旁共用一个图标按钮：空闲时显示三角形且下方提示“播放”，预览期间显示正方形且提示“停止”；按钮只停止自己创建的编辑器预览句柄，不会清掉战斗、菜单或其他游戏音频，因此整首音乐也能试听到用户主动停止。既有独立“播放音效”项目，每个非音效项目也可附加“执行时”或“执行结束时”音效。结束音效按公开持续时间排程但不阻塞列表；长音乐不会因项目结束被主动截断。Seek 重算静音，只有精确创建帧可播一次。

### 13.6 切换敌人贴图与动画

“切换敌人贴图 / 动画”按稳定敌人 UID 选择目标，再选择身体、头、脸、左手、右手或腿。资源模式可设为静态 Sprite 或当前角色目录下的逐帧动画；动画可选择是否循环。列表不保存作者电脑的绝对路径，也不会把另一个角色目录的素材混进选择器。角色或资源改名后由 UID 和资源登记迁移引用。

### 13.7 变量、读取数值与公式

公式聚焦时可从顶栏插入中文描述的变量，不必打开独立大页。内建 token：`time`、`turn`、`soul_x/y/angle`、`player_hp/max_hp/kr/lv/atk/def`、`shield_value/max/natural_max`、`pi`、`e`。具体对象以 `obj_<uid>_<property>` 暴露位置、角度和可读属性。

“读取对象数值”可选择时间/回合、玩家、灵魂、护盾或具体对象和属性，再命名短变量。重名不会静默覆盖，必须明确确认覆盖或重命名。保留名不能覆盖。

变量项目支持设值、加、减、乘、除。公式支持 `+ - * /`、正负号、括号、`random/rand`、`sin/cos/tan`（角度制）、`sqrt`、`log`、`ln`、`abs`、`floor/ceil/round`、`min/max/clamp`、`pow/power`。除零、非法域、未知名字、括号或参数错误均判无效。

### 13.8 条件、循环与连接

条件支持 `== != > >= < <=`，两侧都是公式。成立执行下一项，不成立跳过指定项数。当前没有独立 `else` 节点；现有是 if 式跳过，可配合范围与节点连接组织分支。

循环重复紧随其后的指定项目数，使用循环栈支持嵌套。没有等待时，全部瞬时项目和全部循环轮次在同一逻辑帧执行，不使用固定的每帧项目数节流，也不会擅自等待攻击动画或生命周期结束。循环项可直接填写“每轮额外等待（帧）”，默认 0；循环范围内另放普通等待或“等上一个步骤执行完”也会真实阻塞当前轮并推迟下一轮。节点连接启动目标列表，新列表下一帧处理，不在同一调用栈递归；连接行自身不贡献执行时长，但会把当前并行块最后实际动作的完成时间传给目标列表。

## 14. 时间轴、播放、暂停与 Seek

手动 `duration>0` 时使用指定总长，否则从事件和脚本推导。GB 计入入场+发射前等待+光束+20，斩击计入警告+攻击+10，真刀计入警告+攻击，打字机按纯文本长度/速度估算+15；普通有限事件用 duration，无限事件为时间轴至少贡献 60 帧。

连续非等待步骤在同一个列表时间点启动并并行运行。固定等待只把列表时间游标向后推进作者填写的帧数，已经启动的动画继续在后台重叠；“等上一个步骤执行完”先按当前并行块最长动作的公开时长推进，再追加该等待项填写的额外帧数。估算器分别记录列表游标和所有已启动动作的最晚结束点，不会在固定等待处再次加上整个并行块。只有确实建立补间、物理或生命周期的步骤才贡献持续时间；玩家数值、灵魂模式、蓝魂方向、HUD 开关等运行时立即应用的离散操作即使旧字段仍保留默认 60，也按 0 帧计算。最终自动长度额外加 0.1 秒。时间轴先显示 `编辑 / 定格 / 播放` 状态，再显示 `分:秒.十分之一` 的当前/总长，不显示参数数量串。

空格完整预览会重置下一怪物回合的框、实例、变量、脚本、滤镜与动画基线，并触发游戏开始和目标怪物回合列表。完整编辑器预览结束后冻结末帧，不执行真实回合清理；真实 `turn_test` 完成后结束回合并恢复红魂。

拖动游标时立即从基线无渲染求值到目标帧，并冻结 Step、Alarm、速度和贴图播放。一次求值必须在下一次 Draw 前原子完成，不能把内部计算拆到后续画面并暴露成从 0 到目标点的快速播放。它也不会强制动画到终点；60 帧动画拖到第 30 帧必须停在曲线 50%。松开只结束拖动并补最后位置。对象的“出生时间”与进度条共用 `分:秒.十分之一` 显示和输入格式；直接输入纯数字仍按逻辑帧解释，兼容旧使用方式和旧存档。

在游标处新建的对象记录该帧为出生时间并在本次播放中临时可见；下次播放重新遵守时间。普通退出状态显示所有已编写对象以便编辑，拖坐标不改出生时间。编辑开始时间并按 Enter 会自动跳到新的出生时刻。

暂停是冻结，不是回卷；当前脚本框不被初始化值覆盖。只有重建、恢复玩家回合、退出等明确路径可强制清理 Board。

## 15. 生命周期、模板与运行所有权

排列副本通过统一 `BattleEditor_SpawnEvent` 生成：深复制作者数据，设置适合本次有限或 `-1` 生命周期的公开寿命，设置姿态，赋同一 Control ID，并加入 `runtime_instances`。脚本列表瞬间执行完不代表墙、散射、长廊或 GB 完成，不能下一帧清场；真正的回合结束仍由现有统一清理路径回收所有运行时副本。

Bone 只是默认模板。算法只应用目标具备的公共位置/角度能力，不为新模板复制第二套运行时。系统对象可以控制但不能进入模板列表。

## 16. 渲染、Surface、裁剪与相机

- Board 填充、组合 Mask 和边框分离。
- 框内对象可选择全部框或指定框 UID；选择器支持搜索、逐项、全选、清空和按 Control ID。
- “被裁剪部分无碰撞”开启时不可见部分也不伤害；关闭时只裁视觉。
- 普通弹幕、装饰、打字机按层级进入 Board Surface、框外层或框下层。
- 最终滤镜组合在输出 Surface；模糊复用 Kawase 管线。
- 镜头中心、X/Y 缩放和旋转相互独立；停止时恢复捕获值。
- 输出固定 640×480，不通过相机视野改动解决 2 倍显示。

## 17. 运行时不变量

1. 默认工程不塞测试攻击。
2. UID、Name、Control ID 分工固定，类型参与组身份。
3. 规则形状只在顶点编辑时转 Polygon。
4. 顶点脚本引用 UID，不引用数组下标。
5. 主框/加框/减框共享同一真实 Board 组合。
6. 播放期间普通 Step 不重复同步初始化框覆盖脚本结果。
7. 组拖动是增量；字段提交只同步一个绝对字段。
8. Visual Tint 与 Damage Profile 分离；红色外观不等于秒杀。
9. 光束视觉、射线长度与碰撞宽度分离。
10. Seek 重算不重复播放音效。
11. 伤害/KR/死亡共用一条管线；真刀不复制完整伤害系统。

游戏结束文字仍在逐字显示时即可按 Z 尝试复活。编辑器预览死亡会沿原路径返回编辑器；从正常开始进入的战斗也接受同一提前输入，但仍返回正常战斗，不会启用编辑器专用的强制回合快捷键。
12. 3D/4D 入口只包装已有构造器。
13. 系统对象可控制不可复制。
14. 有限循环不受人为逐帧节流；自连接通过“连接列表下一帧启动”隔开调用栈。
15. 新字段必须有迁移默认，旧项目缺字段不可崩溃。
16. 编译、Runner 实测和用户确认必须分开记录。
